# Review Map Data

When a criterion requires map points, inspect the actual plotted result symbols in the cited map capture. A visible legend or populated details/results panel is insufficient; distinguish result symbols from linked-site markers. An empty map capture must not be captioned or accepted as plotted-point proof. Label any separate broader-scope illustration and narrowly filtered record check honestly, without implying a marker-to-record identity that the images do not establish.

For a source-qualified available/reported field list, distinguish values visibly verified from fields not exercised. Begin a limited-record assessment with `Coverage limited to this record; not exercised: <field names>` and state why each omitted named field was not exercised. Claim a field was not returned only when the supplied evidence includes a reviewable genuine-response observation; otherwise say its availability was not established. Do not require an unreturned optional field, silently waive a mandatory field or imply every named field was verified. A correctly bounded available-fields criterion can pass for its supplied record with this explicit limitation; a separately required conditional branch still needs its matching fixture. Missing readable proof for a value claimed to be present is Unverified, and a directly contradicted mandatory value is Failed.

Use the same coverage standard for every ticket. "Each/every/all" requires a defined genuine scope and reconciliation of all supplied records, including cluster members; sampled visible markers do not prove each record selectable. A complete genuine single-record scope can satisfy the same standard: verify the full point/member counts and successful normal selection rather than inventing a minimum fixture size. It does not establish deployment-wide coverage and must not replace a source-fixed time/area/record scope. Do not accept a sampled Service pass while rejecting the equivalent HTTP/Ping scope. A single marker cannot prove the absence of every other type: inspect the actual settled layer scope and identifiable displayed results, and state exactly what is established without inventing off-viewport requirements. Every named field must be readable, every required comparison/branch represented, and sort proof must show the settled target column and actual ordering rather than a click alone. Treat missing other-layer baselines, editor branches, details-tab states and exact-value proof as coverage gaps, not automatic product defects. Never add an unrelated branch not required by the canonical text.

For numeric marker-colour claims, reconcile the actual plotted marker and normal selection with the genuine point/member/detail response bodies supplied as private supportingEvidence. Check the readable numeric summary and selected Test ID when available, keeping aggregate and member values distinct. A legend, pixel count or tester narrative alone is insufficient; do not reject an auditable raw-response/marker association merely because a separate UI popup does not display the exact aggregate decimal.
